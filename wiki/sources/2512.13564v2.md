# Summary

This survey provides a comprehensive landscape of memory systems for Large Language Model (LLM)-based agents, arguing that traditional taxonomies like long/short-term memory are insufficient for the field's rapid and fragmented growth. The authors propose a new, unified framework for understanding agent memory through the lenses of **Forms, Functions, and Dynamics**.

The paper begins by distinguishing agent memory from related concepts like LLM memory (internal model mechanisms), Retrieval Augmented Generation (RAG, typically static knowledge access), and context engineering (transient resource management). Agent memory is uniquely defined by its focus on maintaining a persistent, self-evolving cognitive state that integrates factual knowledge and experience over time.

The core of the survey is organized around the proposed taxonomy. **Forms** addresses *what* carries memory, identifying three primary implementations: 1) **Token-level memory**, which stores explicit, human-readable units and is sub-categorized by its organizational structure (flat, planar, or hierarchical); 2) **Parametric memory**, where information is encoded directly into model weights, either internally (fine-tuning) or externally (adapters, LoRA); and 3) **Latent memory**, which is carried in the model's internal representations like KV-caches or hidden states, and is categorized by its origin (generated, reused, or transformed).

**Functions** explains *why* agents need memory, moving beyond temporal distinctions to propose three roles: 1) **Factual memory** stores declarative knowledge about the user and environment to ensure consistency and coherence; 2) **Experiential memory** accumulates procedural knowledge from past trajectories (cases, strategies, skills) to enable continual learning and self-evolution; 3) **Working memory** serves as a transient, capacity-limited workspace for active context management during a single task.

**Dynamics** describes *how* memory operates and evolves through a lifecycle of three processes: 1) **Memory Formation**, the encoding of raw experience into structured units; 2) **Memory Evolution**, the integration of new information via consolidation, updating, and forgetting; and 3) **Memory Retrieval**, the context-aware process of querying and post-processing memories to support reasoning.

Finally, the paper compiles key benchmarks and open-source frameworks, and articulates forward-looking frontiers. These include the shift from retrieval-centric to generative memory, the move from handcrafted to automated and RL-driven memory management, and the challenges of creating multimodal, shared, and trustworthy memory systems. The survey's purpose is to provide conceptual clarity and a foundational framework for designing future agentic intelligence.

# Key Claims

- Traditional memory taxonomies (e.g., short-term vs. long-term) are insufficient to capture the diversity and complexity of modern AI agent memory systems.
- A unified framework based on Forms (what), Functions (why), and Dynamics (how) provides a more comprehensive and conceptually clear way to organize the field.
- Agent Memory is a distinct concept from LLM Memory, RAG, and Context Engineering, characterized by its focus on a persistent, self-evolving cognitive state.
- Memory can be physically realized in three forms: explicit token-level units, implicit model parameters (parametric), or internal hidden states (latent).
- The functional roles of memory are best categorized as factual (knowledge), experiential (self-improvement), and working (active context).
- The memory lifecycle is a dynamic process involving three key stages: formation (encoding), evolution (refining), and retrieval (accessing).
- The field is shifting from hand-crafted memory management pipelines toward automated, self-optimizing systems, increasingly driven by Reinforcement Learning (RL).
- Future research frontiers for agent memory include generative memory, multimodal integration, shared memory for multi-agent systems, and establishing trustworthiness.

# Mechanisms

- **Memory Formation:** The process of converting raw experience into memory units. This includes:
    - *Semantic Summarization*: Compressing long text into a compact summary.
    - *Knowledge Distillation*: Extracting specific facts, insights, or strategies from trajectories.
    - *Structured Construction*: Organizing information into graphs, trees, or other explicit topologies.
    - *Latent Representation*: Encoding experience into machine-native vectors or KV-cache states.
    - *Parametric Internalization*: Embedding knowledge directly into model weights via fine-tuning or model editing.

- **Memory Evolution:** The dynamic maintenance of the memory base. This involves:
    - *Consolidation*: Merging new and existing memories to form more generalized insights or reduce redundancy.
    - *Updating*: Resolving conflicts between new and old information to maintain factual accuracy.
    - *Forgetting*: Pruning outdated, low-value, or irrelevant information based on criteria like time, access frequency, or importance.

- **Memory Retrieval:** The process of accessing and using stored information. It is described as a four-stage pipeline:
    1.  **Retrieval Timing and Intent**: Deciding when to retrieve and which memory store to query.
    2.  **Query Construction**: Rewriting or decomposing the initial query to better align with the memory index.
    3.  **Retrieval Strategies**: Executing the search using lexical, semantic, graph-based, or hybrid methods.
    4.  **Post-Retrieval Processing**: Re-ranking, filtering, and aggregating the retrieved results to form a concise and coherent context for the LLM.

# Useful Examples

- **Factual Memory:** *MemGPT* uses a virtual, OS-like memory system to manage dialogue history, moving less relevant information from a main context (working memory) to an external context (long-term memory) to avoid overflow.
- **Experiential Memory (Skills):** *Voyager* builds an ever-growing library of executable skill code snippets by exploring the Minecraft environment. These skills can be retrieved and reused to solve new tasks more efficiently.
- **Experiential Memory (Reflection):** *Reflexion* stores action trajectories and uses an LLM to generate textual self-reflections on failures. These reflections are added to a long-term memory buffer to guide future attempts and prevent repeated mistakes.
- **Hierarchical Token-level Memory:** *G-Memory* uses a three-tier graph structure (insight, query, interaction) for multi-agent systems, allowing agents to access shared experiences at different levels of abstraction.
- **Latent Memory:** *MemGen* uses a "memory weaver" module (a LoRA adapter) to dynamically generate and insert latent memory tokens directly into the agent's reasoning stream without explicit retrieval from an external text store.
- **Working Memory:** *HiAgent* implements a hierarchical working memory organized by subgoals. When a subgoal is completed, its detailed action-observation trace is compressed into a summary, keeping the active context window focused and manageable for long-horizon tasks.
- **Memory Evolution:** *Zep* uses a Temporal Knowledge Graph that, instead of deleting conflicting facts, marks them with invalid timestamps. This preserves historical context while ensuring the agent reasons with the most current information.

# Possible Relevance

- **AI agent design:** This paper is a foundational text for designing memory architectures. The "Forms, Functions, Dynamics" framework provides a clear vocabulary and design space for building agents. For example, one could use token-level memory for debuggability, integrate experiential memory for self-improvement, and use RL-driven dynamics for autonomous management. The distinction between retrieval and generative memory is key for designing next-generation systems.
- **Narrative systems:** The functional taxonomy is directly applicable to creating persistent, evolving characters. *Factual memory* can be a knowledge graph tracking plot events and character relationships. *Experiential memory* allows an agent to "learn" from past narrative events, changing its behavior or goals. This provides a mechanism for dynamic character arcs in a serialized narrative.
- **Game mechanics:** Experiential memory provides a blueprint for NPC and agent learning. A *skill-based* memory (like Voyager) can be a core game mechanic where an AI companion learns new abilities. *Shared memory* is directly relevant for designing cooperative AI squads that need to coordinate by sharing information about the game state (e.g., enemy positions, discovered resources) on a "blackboard."
- **Knowledge management:** The paper's structural categories for token-level memory (flat, planar, hierarchical) offer powerful metaphors for organizing a personal knowledge wiki. A personal Zettelkasten could be viewed as evolving from a flat collection of notes to a planar graph of links, and finally to a hierarchical system with MOCs (Maps of Content) representing abstracted insights, mirroring the memory consolidation process.
- **Industrial/Ruhr region context:** This source has no direct relevance to the industrial or Ruhr region context. It is a general survey of AI research.
