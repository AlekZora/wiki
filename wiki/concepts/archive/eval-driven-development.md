## Definition

Eval-driven development is a systematic methodology for building and improving AI agent capabilities through structured test cycles. Adapted from OpenAI's framework, the cycle has four steps: 1) **Define Metrics** — specify what success looks like for the agent task; 2) **Create the Skill** — write the knowledge artifact or prompt change; 3) **Test with Evaluations** — run the agent against predefined scenarios; 4) **Grade & Iterate** — assess outputs using deterministic assertions or an LLM-as-a-judge, then refine. Automated eval harnesses run agents under different conditions (e.g., with and without a skill) and assert behavioral differences.

## How I Think About It

This is TDD for agents. The core insight is that agent behavior is hard to verify by inspection alone — you need to actually run the agent and check its outputs systematically. Without evals, you're shipping blind. Evals are the difference between "I think this skill works" and "I can prove this skill works, and I'll know if a future change breaks it."

The LLM-as-a-judge pattern fills in where deterministic assertions can't — for open-ended outputs, you ask another model to evaluate quality. The two approaches are complementary: deterministic for structural checks (does the SQL contain `security_invoker`?), LLM judge for semantic checks (is the response appropriate for the user's tone?).

## Project Connection

Evals are directly applicable to testing AI character agents in the sci-fi series. Each character could have a suite of "behavioral evals" — specific scenarios where their response must reflect their hidden agenda, personality, and knowledge state. This creates a CI-like pipeline for ensuring character consistency as the series evolves.
